# 本地生活服务智能体 - 项目介绍

> 基于 OpenClaw 的本地生活管家 Agent · 让 1 句话替代 10 个 App

---

## 一、项目速览（One-Pager）

| 项目维度 | 内容 |
|---------|------|
| **项目名称** | 新城市生活助手（基于 OpenClaw 的本地生活管家 Agent） |
| **一句话定位** | 用自然语言对话替代点评/地图/打车/天气等多个 App 的本地生活服务入口 |
| **核心框架** | OpenClaw v2.7.1（开源智能体框架，IM 原生交互） |
| **技术规范** | AgentSkills 兼容规范（YAML frontmatter + Markdown 正文 + references 数据） |
| **核心模型** | LongCat-2.0-Preview（128K 上下文，适配多 Skill 联合推理） |
| **交互渠道** | 微信、飞书、钉钉等 50+ IM 平台（OpenClaw 原生支持） |
| **Skill 数量** | 8 个本地生活 Skill + 1 套共享虚拟城市数据层（赛题要求 ≥3） |
| **运行依赖** | Python 3.10+（沙盒）、Node.js 16+（辅助脚本）、OpenClaw 网关 |
| **数据来源** | 全模拟数据（25 餐厅 / 18 场所 / 4 地铁线 / 6 城区），不接入任何真实 API |
| **目标用户** | 一二线城市 25-40 岁白领，重视时间效率、有本地生活品质诉求 |

## 二、用户痛点 & 我们的解法

### 2.1 三大用户痛点

| 痛点 | 现状 | 后果 |
|------|------|------|
| **App 孤岛** | 餐饮看点评、出行看地图、打车用滴滴、天气看墨迹 | 信息分散、决策割裂 |
| **决策疲劳** | 反复比较餐厅、算路线、查优惠、协调时间 | 1 次约会要花 15 分钟准备 |
| **被动检索** | 只能等用户主动打开 App 查询 | 错过变化、错失机会 |

### 2.2 OpenClaw 提供的解药

| OpenClaw 能力 | 对应痛点 | 本项目如何用 |
|--------------|---------|-------------|
| IM 原生交互 | App 孤岛 | 用户在微信/飞书/钉钉直接发对话，无需打开任何 App |
| Skill 插件扩展 | 决策疲劳 | 8 个 Skill 协同，一次输出完整方案 |
| Always-on 持续运行 | 被动检索 | 后台 7×24 监控餐厅排队/天气/优惠，主动推送 |
| 统一会话上下文 | 决策疲劳 | 跨 Skill 约束传播、预算统一分配、冲突自动解决 |

## 三、核心能力全景（5 大亮点）

### 亮点 1：专属管家"小橙"人设（不是 AI 客服，是朋友）

管家有鲜明的人格：

| 特质 | 表现 | 真实对话示例 |
|------|------|-------------|
| 靠谱 | 给建议时笃定 | "就去意面工坊，不会错的" |
| 暖 | 主动考虑用户没想到的细节 | "下雨了记得带伞，地铁口到餐厅还有 200 米" |
| 接地气 | 口语化、不端着 | "这家水煮牛肉绝了" |
| 有主见 | 用户纠结时直接帮做决定 | "我帮你定——就这家！" |
| 记性好 | 跨会话记住偏好 | "上次你说不吃辣，今天还是避开川菜吧" |

**对比传统 AI 客服**："尊敬的用户，您好，您有以下 5 个推荐选项..."

### 亮点 2：三级联动架构（不是 8 个 Skill 简单拼接）

```
Layer 3: 编排联动  ← life-service-query 作为中枢，编织时间线、自动解决冲突
Layer 2: 推理联动  ← 天气/预算/人员等约束跨 Skill 自动传播
Layer 1: 数据联动  ← 所有 Skill 共享虚拟城市坐标
```

**一个真实场景**："明天下雨" → 出行自动禁骑行、餐饮推外卖、娱乐排除户外场所、整条方案自动重算。

### 亮点 3：7×24 自主协同（突破一问一答）

后台任务支持**持续监控 → 条件满足 → 主动推送 → 自动执行**的连贯流程。

**经典场景**："我想去海底捞但怕排队"
```
[19:00] 用户：帮我盯着
[19:01] 小橙：好嘞，我帮你盯着！排15桌，到5桌叫你

(后台默默监控，19:05→15桌, 19:15→10桌, 19:30→7桌, 19:42→4桌)

[19:42] 小橙：海底捞剩4桌了！要帮你叫车吗？¥35, 20分钟到
[19:43] 用户：叫吧
[19:43] 小橙：车已叫好，8分钟到楼下，取号也帮你办好了~
```

### 亮点 4：动态模拟沙盒（不是静态 JSON）

基于 FastAPI 自建 Mock 后端，**真正的时间维度模拟**：

| 数据维度 | 动态机制 |
|---------|---------|
| 餐厅排队 | 每家独立状态机，每 10 分钟自动切换"增/稳/减"趋势 |
| 路况 | 根据当前时间自动应用早高峰×1.8 / 晚高峰×1.6 / 夜间×0.8 |
| 天气 | 加入随机波动和 10% 概率的突发天气事件 |
| 城市事件 | 从 10 个模板中随机生成（特价/拥堵/限流/加映等） |

### 亮点 5：跨会话长尾偏好记忆（让管家"认识你"）

7 大记忆维度：口味 / 消费 / 通勤 / 生活 / 家庭 / 娱乐 / 特殊日期

- **被动捕获**：从对话中自动提取（"我不吃香菜" → 自动记录）
- **主动询问**：首次使用自然地问（"对了你平时能吃辣吗？"）
- **冲突解决**：临时偏好 > 长期记忆（"今天例外"不覆盖长期设定）

### 场景 A：周末约会一站式安排
```

来帮你编排完整约会方案！预算600/2人，按约会场景分配：
餐饮270(45%) + 娱乐210(35%) + 出行60(10%) + 备用60(10%)

下午1点先去陶艺工坊，一起做陶艺，互动又有纪念品，大概2小时~
出来走15分钟就到美术馆，当代艺术展边看边聊，逛到5点差不多
然后晚餐我给你定了意面工坊，有露台位，日落的时候去特别浪漫
吃完走5分钟就是万达影城，8点10分那场人最少

总计 ¥696 → 用联票优惠后 ¥598，在预算内！
交通：步行+地铁 ¥10/人 | 打车 ¥30/人
傍晚转凉，建议带薄外套
```

| 操作场景 | 传统 App 交互 | 本项目智能体 | 提升幅度 |
|---------|------------|-------------|---------|

## 七、5 分钟快速运行

```bash
# 1. 启动动态沙盒
cd sandbox
pip install -r requirements.txt
uvicorn main:app --port 8900 --reload &
# 验证: curl http://localhost:8900/api/dashboard

# 2. 启动 OpenClaw 网关（按 OpenClaw 官方指引）
# 将 skills/ 目录注册到 OpenClaw 的 skill 搜索路径
# 加载 SOUL.md 作为默认人设

# 3. 在 IM（飞书/微信/钉钉）发起对话
# "今天中午吃什么" → 验证餐饮推荐
# "帮我盯着海底捞排队" → 验证 7×24 监控
```

详细部署与 OpenClaw 集成见 [技术文档.md](./技术文档.md)。

## 八、数据安全声明

| 措施 | 详细说明 |
|------|---------|
| 全模拟数据 | 25 餐厅 / 18 场所 / 4 地铁线 / 天气 / 优惠 均为虚构 |
| 无真实 API 调用 | 不接入美团/高德/天气/支付等任何真实第三方 API |
| 无用户信息收集 | 不收集姓名、手机号、地址等任何真实个人信息 |
| 偏好本地存储 | 偏好仅存储在 `~/.openclaw/memory/user-preferences.json` |
| 坐标虚拟化 | 虚拟城市坐标不对应任何真实地理位置 |
| 价格虚构 | 所有价格为模拟设定，不反映真实市场价格 |

## 十、风险与边界（诚实说明）

| 风险项 | 当前状态 | 应对方案 |
|--------|---------|---------|
| OpenClaw 框架集成 | 需按 OpenClaw 官方文档接入 skill 路径 | 提供完整运行指引，详见 [技术文档.md §三](./技术文档.md) |
| 模型幻觉 | LLM 仅做理解与编排，精确计算由辅助脚本完成 | 餐厅/价格/距离/时间均走本地 JSON + Node.js 脚本 |
| 沙盒进程依赖 | 7×24 监控依赖沙盒 API 在线 | 已实现优雅降级（API 不可用时使用模拟数据） |
| 跨会话偏好持久化 | 依赖本地文件系统 | 偏好文件备份即恢复，未上云 |
| 多用户隔离 | 当前为单用户设计 | 可按 user_id 拆 JSON 文件即可扩展 |
| 真实场景适配 | 当前为虚拟城市，迁移到真实城市需替换数据源 | 替换 `city-map.json` + `weather-simulation.json` 即可 |
