## 演示前 5 分钟检查清单

### 硬件与软件
- [ ] 电脑电源连接（避免演示中途休眠）
- [ ] 关闭无关通知（Slack、邮件、IM）
- [ ] 屏幕设置为「不自动锁屏」
- [ ] 网络稳定（建议手机热点备份）
- [ ] 演示窗口最大化到 1920×1080

### 服务检查
- [ ] **沙盒启动**：`cd sandbox && uvicorn main:app --port 8900`
- [ ] **沙盒验证**：`curl -s http://localhost:8900/api/dashboard | head -5`
- [ ] **OpenClaw 网关**：进程存活
- [ ] **Skill 已加载**：`openclaw skill list` 看到 8 个
- [ ] **SOUL.md 已加载**：管家人设"小橙"就绪
- [ ] **IM 客户端**已登录（飞书/钉钉/微信任一）

### 数据准备
- [ ] 偏好文件已 reset：`node preference-manager.js reset`
- [ ] 任务状态已清空：`rm -f skills/.../task-state.json`
- [ ] 新开一个对话（`/new`）作为演示专用

- [ ] 终端 A：IM 客户端（演示对话）

- [ ] 浏览器 tab：沙盒 `http://localhost:8900/docs`（备查）

## 场景 1：全场景编排 + 人设（2 分钟，T=0:30 → 2:30）

### 目标
展示：① 管家"小橙"人设 ② 一句话触发完整方案 ③ 三级联动 ④ 预算智能分配

### T=0:35 输入
```
明天周六，和女朋友约会，下午1点到晚上9点，预算600两个人
```

### 观察要点（边观察边向评委口播）
- ✅ 是否以口语化开场（"我先看了下..." 而非"为您查询"）
- ✅ 是否自动查天气开场
- ✅ 是否给出预算分配（45/35/10/10）
- ✅ 是否输出完整时间线（4 环节：陶艺 → 美术馆 → 意面工坊 → 万达影城）
- ✅ 是否用故事体叙述（"下午 1 点先去...然后...接着..."）
- ✅ 是否在预算内或主动说明超预算后用优惠调整

### T=1:30 追问 1（测试对话风格）
```
餐厅那家有什么推荐菜？
```
- ✅ 是否展开具体菜品（"奶油蘑菇意面绝了" 而非"推荐菜品如下"）
- ✅ 是否有贴心细节（"靠窗位子光线好，记得备注"）

### T=1:50 追问 2（测试跨 Skill 联动）
```
吃完饭怎么去电影院？
```
- ✅ 是否自动切到出行规划
- ✅ 距离/时间是否合理（基于虚拟城市坐标）
- ✅ 是否对比多种交通方式

### T=2:20 过渡话术
> "刚才这套方案一口气触发了 5 个 Skill：天气感知、餐饮推荐、娱乐推荐、出行规划、优惠比价。下面我演示**天气突变**时，方案怎么自动调整。"

## 场景 2：天气突变联动（1 分钟，T=2:30 → 3:30）

### 目标
展示：天气变化触发**全链路自动调整**（不是"打个补丁"）

### T=2:35 输入
```
等等，我刚看天气预报说明天下雨，方案还能用吗？
```

### 观察要点
- ✅ 是否识别天气变化并自动调整
- ✅ 调整是否覆盖所有环节：
  - 户外活动 → 室内
  - 步行段 → 地铁/打车
  - 餐厅优先级（外卖选项提醒）
- ✅ 过渡是否自然（"下雨啊...帮你调一下" 而非"由于天气原因系统已调整"）
- ✅ 是否给出调整后的总费用
- ✅ 是否有"带伞"等贴心提示

### T=3:10 收尾问
```
那就按这个来吧，还有什么要注意的吗？
```
- ✅ 是否记得之前所有偏好
- ✅ 是否给出带伞/提前出门/地滑等提醒

### T=3:25 过渡
> "天气变一下，整套方案就自动重排了——这就是**联动**的威力。下面看更刺激的：**预算压缩到 400**。"

## 场景 3：预算优化（1 分钟，T=3:30 → 4:30）

### 目标
展示：超预算时不简单拒绝，而是**智能降级 + 优惠组合**

### T=3:35 输入
```
预算只有400两个人怎么办？
```

### 观察要点
- ✅ 不直接拒绝（"别急，帮你用优惠压一压"）
- ✅ 降级链是否体现：出行降级（打车→地铁）→ 娱乐降级（收费→免费）→ 优惠方案
- ✅ 是否展示"原价 vs 优化后"对比
- ✅ 降级后体验是否仍然体面（不是穷游）
- ✅ 是否暖心收尾（"省了 2 块可以买瓶水😄"）

### T=4:10 收尾确认
```
可以，就这个方案了！
```

### T=4:20 过渡
> "3 句话搞定 1 整天约会。这是被动的部分。下面展示 7×24 主动的部分——**排队监控**。"

## 场景 4：7×24 自主协同（2 分钟，T=4:30 → 6:30）

### 目标
展示：突破一问一答 → 后台任务持续监控 → 条件触发 → 自动推送 → 自动叫车

### 步骤 1：启动监控（T=4:30）
```
我想去海底捞但怕排队，帮我盯着
```
- ✅ 管家是否主动表示"帮你盯着"
- ✅ 是否说明监控策略（每 5 分钟检查，剩 5 桌叫你）
- ✅ 语气像朋友（"好嘞，我帮你盯着！"）

### 步骤 2：演示后台调度器（T=4:50）

切到 **终端 C**，执行：
```bash
cd skills/always-on-scheduler/scripts
node task-scheduler.js simulate
```

### 边演示边向评委口播
> "现在大家看终端——后台任务调度器正在模拟从 19:05 到 19:48 的排队变化。"

**预期输出节奏**：
- 19:05 - 15 桌 ⏳
- 19:15 - 12 桌 ⏳
- 19:25 - 10 桌 ⏳
- 19:35 - 8 桌 ⏳
- 19:42 - 6 桌 ⏳
- 19:48 - **4 桌 ⚡ 触发！**

触发后调度器会：
1. 推送消息给用户
2. 计算从家到海底捞的路线
3. 自动叫车（生成车辆信息、ETA、费用）
4. 远程取号

### 步骤 3：用户确认（T=5:40）
切回 IM 客户端：
```
叫吧
```
- ✅ 是否自动调用叫车服务
- ✅ 是否返回车辆信息和预计到达时间
- ✅ 是否附带远程取号结果

### 步骤 4（可选）：展示沙盒动态数据（T=6:10）

切到浏览器，访问 `http://localhost:8900`：
- `/api/queue/R13`：排队状态实时变化
- `/api/traffic`：路况根据时间段动态调整
- `/api/events`：随机生成的城市生活事件
- `/api/dashboard`：综合状态面板

> "这就是我们的动态模拟沙盒——不是静态 JSON，是真正在时间维度上演化的数据。"

### T=6:25 过渡
> "排队监控→提醒→叫车→取号，**一条龙**，没人催没人问。最后一个能力——让管家真正**认识你**。"

## 评分标准自评（参考）

| 维度 | 优秀（90+） | 良好（75+） | 及格（60+） |
|------|------------|------------|------------|
| **功能完整性** | 8 个 Skill 全部被触发 | 6 个以上 | 4 个以下 |
| **联动效果** | 天气→全链路自动调整 | 部分调整 | 无调整 |
| **预算优化** | 自动降级+优惠，预算内 | 有降级但超预算 | 直接拒绝 |
| **对话风格** | 朋友式，"小橙"人格一致 | 中性，偶有生硬 | 客服/机器人感 |
| **7×24 协同** | 监控→提醒→叫车→取号完整 | 有提醒但流程不全 | 无后台任务 |
| **偏好记忆** | 跨会话自动应用，有"认识你"感 | 同会话内记住 | 每次从零开始 |
| **动态沙盒** | 排队/路况/事件实时变化 | 部分 API 可用 | 纯静态数据 |
| **时间线** | 故事体叙述 | 清单式但合理 | 混乱 |
| **数据一致** | 价格/距离/时间自洽 | 小偏差 | 明显矛盾 |

## 风险预案（最坏情况应对）

### 预案 A：LLM 推理超时

**症状**：发出问题后 30 秒无回复

**应对**：
1. 立即切换到「备选演示 A：通勤场景」（已在 [§备选](#备选演示) 列出）
2. 备选输入："明天上班怎么走最快？"
3. 这是更短的链路（2 个 Skill），通常 10 秒内出

### 预案 B：沙盒 API 不可用

**症状**：`curl http://localhost:8900/api/queue/R13` 返回 connection refused

**应对**：
1. 终端 C 跑： `cd sandbox && uvicorn main:app --port 8900 &`
2. 等 5 秒再试
3. 如果还失败，**跳过场景 4 沙盒演示**，用文字描述代替：
   > "现在 7×24 调度器在轮询沙盒。正常情况下排队 15→12→10→8→6→4 桌时触发提醒，并自动叫车。我们直接看调度器本地模拟——"

### 预案 C：某 Skill 未触发

**症状**：输入"今天中午吃什么"但回复了娱乐推荐

**应对**：
1. 重新措辞输入："帮我推荐个吃午饭的餐厅"
2. 或者直接描述 SKILL.md 加载过程（口播兜底）：
   > "大家可以看到我们的 8 个 Skill 通过 description 关键词匹配，这里触发了 food-order-recommendation。"

### 预案 D：`/new` 命令不可用

**症状**：IM 客户端没有 `/new` 命令

**应对**：
1. 改用 "清空上下文" 或 "忘记之前对话"
2. 或者提前 1 分钟开 2 个独立对话窗口，先用 1 个做偏好植入，演示时切到第 2 个

### 预案 E：评委现场提问

如果评委问"为什么不用真实 API"，回答：
> "赛题要求数据安全、不收集真实用户信息。虚拟城市能完整展示推理能力，避免了 API 依赖和数据隐私风险。"

如果评委问"模型幻觉怎么处理"：
> "所有数据来自本地 JSON（city-map.json），LLM 只做理解和编排，精确计算由 Node.js 脚本完成，从源头减少幻觉。"

如果评委问"和直接调推荐算法比优势在哪"：
> "本项目核心价值不是推荐准确度，而是**跨场景编排能力**——一个约束变化触发全链路自动调整，这是传统推荐系统做不到的。"
