# 基于 OpenClaw 的本地生活「全天候私人管家」技术文档

> 本文档面向工程师 / 评委，介绍系统架构、Skill 设计、部署集成与扩展方式。

---

## 一、项目概述

### 1.1 项目定位

**新城市生活助手**是基于 OpenClaw 开源智能体框架构建的本地生活服务智能体，核心理念为**"用一句话替代十个App"**。用户通过自然语言对话即可完成餐饮推荐、出行规划、娱乐安排、优惠比价等全场景生活服务，从"用户找服务"转变为"服务找用户"。

### 1.2 技术选型一览

| 维度 | 选型 | 理由 |
|------|------|------|
| Agent 框架 | [OpenClaw](https://github.com/anthropics/openclaw) v2.7.1 | IM 原生交互 + Skill 插件扩展 + Always-on + 50+ IM 兼容 |
| LLM | LongCat-2.0-Preview | 128K 上下文，适配多 Skill 联合推理 |
| 沙盒后端 | FastAPI + Uvicorn | 轻量、动态、Python 生态成熟 |
| 辅助脚本 | Node.js 16+ | OpenClaw 工具链默认环境，可直接通过 Bash 工具调用 |
| 数据 | 全本地 JSON | 数据安全 + 零外部依赖 + 易扩展 |
| 部署 | 本地 | Skills 存放于 `~/.openclaw/skills/`，沙盒监听 `localhost:8900` |

### 1.3 核心技术规范

- 所有 Skill 严格遵循 **AgentSkills 兼容规范**（YAML frontmatter + Markdown 正文 + references/ 数据）
- 数据层采用**共享虚拟城市**设计，所有 Skill 基于同一地理坐标系统做空间推理
- 交互层遵循统一的**交互体验规范**（`interaction-guidelines.md`），保证对话风格一致
- Prompt + 脚本混合架构：LLM 负责理解与编排，Node.js 脚本负责精确计算，互补而非替代

## 三、部署与 OpenClaw 集成

### 3.1 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Python | 3.10+ | 沙盒后端 |
| Node.js | 16+ | 辅助计算脚本 |
| OpenClaw | v2.7.1+ | Agent 网关 |
| 内存 | ≥2GB | LLM 推理 |
| 网络 | 需访问模型 API | LLM 调用 |

### 3.2 部署步骤

```bash
# ========== Step 1: 启动动态沙盒 ==========
cd sandbox
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8900 --reload
# 验证: curl http://localhost:8900/api/dashboard
# 预期: 返回 JSON 包含 weather/traffic/queues/events

# ========== Step 2: 注册 Skill 到 OpenClaw ==========
# 方法 A: 软链接到 OpenClaw 默认 skill 路径
mkdir -p ~/.openclaw/skills
ln -s $(pwd)/skills/* ~/.openclaw/skills/

# 方法 B: 在 OpenClaw 配置文件中指定 skill 搜索路径
# 编辑 ~/.openclaw/config.yaml:
# skills:
#   search_paths:
#     - /path/to/project/skills

# ========== Step 3: 加载 SOUL.md 作为默认人设 ==========
# 方式 A: 复制到 OpenClaw 全局人设目录
mkdir -p ~/.openclaw/soul
cp SOUL.md ~/.openclaw/soul/default.md

# 方式 B: 在 OpenClaw 网关启动参数中指定
openclaw gateway start --soul $(pwd)/SOUL.md

# ========== Step 4: 启动 OpenClaw 网关 ==========
openclaw gateway start
# 网关默认监听 8080 端口
# 验证: curl http://localhost:8080/health
```

### 3.3 验证清单

部署完成后，按下表逐项验证：

| # | 验证项 | 命令 | 预期结果 |
|---|--------|------|---------|
| 1 | 沙盒存活 | `curl http://localhost:8900/api/dashboard` | 返回 JSON 200 |
| 2 | Skill 已加载 | `openclaw skill list` | 看到 8 个 skill 名称 |
| 3 | SOUL.md 已加载 | `openclaw soul show` | 显示 "小橙" 人设 |
| 4 | 简单对话 | 在 IM 发送"今天中午吃什么" | 触发餐饮推荐 |
| 5 | 7×24 监控 | `cd skills/always-on-scheduler/scripts && node task-scheduler.js simulate` | 看到排队递减 + 触发 + 叫车 |

### 3.4 常见部署问题

| 现象 | 排查方向 |
|------|---------|
| Skill 未被识别 | 检查 `~/.openclaw/skills/` 是否含所有 skill 目录 |
| 沙盒 502 | 检查 8900 端口是否被占用，`lsof -i :8900` |
| Node 脚本报错 | 检查 Node 版本 `node --version` ≥ 16 |
| LLM 推理慢 | 优先用本地模型，或就近选择 API 端点 |
| 跨会话偏好不持久 | 检查 `~/.openclaw/memory/` 目录写权限 |

| 文件 | 内容 | 说明 |
|------|------|------|

| `shared/interaction-guidelines.md` | 交互体验规范 | 6 大原则 / 10 条禁忌 / 回复模板 |
| `shared/skill-protocol.md` | Skill 间数据传递协议 | 统一 JSON 消息格式 / 约束条件标准 |

### 4.3 各 Skill 核心能力详解

#### 餐饮推荐 (food-order-recommendation)
- **8 维场景约束**：预算 / 菜系 / 人数 / 天气 / 位置 / 时间 / 外卖 / 儿童友好
- **点餐方案**：N 人点 N+1 菜（荤素冷热的平衡公式）
- **联动触发**：推荐后主动触发出行 / 娱乐 / 优惠 Skill

#### 出行规划 (commute-planning-assistant)
- **4 种交通方式实时对比**：地铁 / 打车 / 骑行 / 步行（含费用、时间、路况系数）
- **多目的地串联**：贪心最近邻算法，自动优化折返
- **路况模拟**：早高峰 ×1.8 / 晚高峰 ×1.6 / 平峰 ×1.0 / 夜间 ×0.8
- **天气适配**：雨天禁骑行、暴雨仅地铁、高温避步行

#### 娱乐推荐 (leisure-activity-recommendation)
- **5 种人员画像**：约会 / 聚会 / 亲子 / 独处 / 团建 → 不同推荐策略
- **时间线编排**：按时段串联场所，校验营业时间 + 场景过渡
- **自动在时间线中插入用餐推荐**

#### 生活服务 (life-service-query) — 编排中枢
- **双重角色**：独立回答生活百科 + 跨 Skill 编排中枢
- **预算智能分配**：约会(餐 45% + 乐 35% + 行 10% + 备 10%)
- **冲突解决链**：超预算 → 降出行 → 降娱乐 → 降餐饮 → 应用优惠
- **9 步编排流程**：天气感知 → 意图解析 → 预算分配 → 娱乐编排 → 餐饮插入 → 路线串联 → 优惠计算 → 冲突检测 → 方案输出

#### 天气感知 (weather-awareness)
- **7 天模拟天气预报**（晴 / 雨 / 暴风 / 高温 / 低温 / 大雾）
- **场景影响引擎**：天气 → 餐饮 / 出行 / 娱乐的策略映射
- **第一推动力**：天气变化触发全方案自动调整

#### 优惠比价 (deal-finder)
- **三级优惠体系**：单店满减 / 组合联票 / 出行优惠
- **预算优化器**：自动在预算内最大化体验质量
- **降级策略**：超预算时自动推荐替代方案并计算节省金额

#### 7×24 自主调度 (always-on-scheduler)
- **5 个定时任务**：早安播报 / 天气突变检测 / 特殊日期提醒 / 周末推荐 / 预算追踪
- **3 个事件监控器**：餐厅排队监控 / 通勤路况监控 / 优惠到期监控
- **任务状态机**：`PENDING → WATCHING → TRIGGERED → EXECUTING → NOTIFIED → COMPLETED`
- **连贯流程**：监控排队 → 剩 5 桌提醒 → 自动叫车 → 远程取号

#### 用户偏好记忆 (user-preference-memory)
- **7 大记忆维度**：口味 / 消费 / 通勤 / 生活 / 家庭 / 娱乐 / 特殊日期
- **被动捕获**：从对话中自动提取偏好（"我不吃香菜" → 自动记录）
- **主动询问**：首次使用时自然地询问忌口和偏好
- **记忆应用**：自动过滤不喜欢项、使用默认地址、检查特殊日期

## 五、辅助计算脚本

为弥补纯 LLM 推理在精确计算上的不足，项目提供 6 个 Node.js 辅助脚本，可通过 OpenClaw 的 Bash 工具调用：

### 5.1 `shared/scripts/city-utils.js`
城市数据工具库，提供精确的空间计算：
```bash
# 计算两地距离（含各交通方式预估时间）
node city-utils.js distance R06 V01

# 搜索附近场所（按类型 + 半径 + 条件筛选）
node city-utils.js nearby restaurant "116.46,39.91" 2

# 条件筛选（菜系 / 价格 / 评分 / 标签）
node city-utils.js search restaurant '{"cuisine":"川菜","max_price":100}'

# 多目的地最优路线排序
node city-utils.js route home R06 V01 V05
```

### 5.2 `commute-planning-assistant/scripts/route-planner.js`
出行路线规划器，支持路况和天气影响：
```bash
# 单程规划（对比 4 种交通方式）
node route-planner.js single home office peak_morning

# 多目的地串联（自动选最优交通）
node route-planner.js multi home R06 V01 peak_evening

# 通勤路线（家→公司，默认早高峰）
node route-planner.js commute peak_morning rain
```

### 5.3 `deal-finder/scripts/deal-calculator.js`
优惠计算器，处理复杂的组合优惠逻辑：
```bash
# 查询单店优惠
node deal-calculator.js query R06

# 计算多项目组合优惠
node deal-calculator.js combo R06 V01 V05

# 预算优化（给定预算自动降级方案）
node deal-calculator.js optimize 400 '[{"id":"R06","price":240},...]'
```

### 5.4 `weather-awareness/scripts/weather-impact.js`
天气影响计算器，量化天气对各维度的影响：
```bash
# 分析天气对通勤 / 餐饮 / 娱乐的影响
node weather-impact.js analyze rain

# 天气联动建议
node weather-impact.js suggest storm leisure

# 根据天气自动调整已有方案
node weather-impact.js adjust '{"items":[...]}' rain
```

### 5.5 `user-preference-memory/scripts/preference-manager.js`
偏好管理器：提取 / 更新 / 查询 / 重置
```bash
node preference-manager.js show
node preference-manager.js update taste '{"likes":["川菜","日料"],"dislikes":["香菜"]}'
```

## 六、动态模拟沙盒

### 6.1 架构概述

沙盒基于 FastAPI 搭建，模拟真实世界中不断变化的动态数据。

| 端点 | 方法 | 功能 | 动态特性 |
|---------|------|------|----------|
| `/api/queue/{id}` | GET | 餐厅排队查询 | 排队桌数随时间自动变化（增 / 减 / 稳） |
| `/api/queue` | GET | 全部餐厅排队 | 综合视图 |
| `/api/queue/{id}/simulate` | POST | 手动设置排队（演示用） | 强制设置基线 |
| `/api/traffic` | GET | 路况查询 | 根据时间段动态调整拥堵系数 |
| `/api/weather/realtime` | GET | 实时天气 | 加入随机波动和突发事件模拟 |
| `/api/weather/alerts` | GET | 天气预警 | 30% 概率生成预警 |
| `/api/car/call` | POST | 模拟叫车 | 生成车辆信息 / ETA / 费用 |
| `/api/car/status/{id}` | GET | 车辆状态 | 模拟状态推进（dispatched → approaching → arrived） |
| `/api/reservation` | POST | 模拟预约 / 取号 | 生成排号 / 计算等候时间 |
| `/api/events` | GET | 动态事件流 | 每次返回 count 个新事件 |
| `/api/events/stream` | GET | 事件流 | 单事件推送（模拟实时） |
| `/api/dashboard` | GET | 综合状态面板 | 一次获取所有动态信息 |
| `/api/demo/simulate-queue-flow` | POST | 演示模式 | 模拟 10 分钟内排队变化 |

### 6.3 核心动态机制

**排队状态模拟**：每家餐厅维护独立的排队状态机：
```python
class RestaurantState:
    base_queue = 初始随机值
    trend = "increasing" | "stable" | "decreasing"
    trend_speed = 每分钟变化桌数
    # 每 10 分钟自动切换趋势
    # 基于 (now - last_update) 计算当前桌数
```

**路况时间模拟**：
```python
if 7 <= hour <= 9:    congestion_car = 1.5~2.2  # 早高峰
elif 17 <= hour <= 19: congestion_car = 1.4~2.0  # 晚高峰
elif 22 <= hour <= 6:  congestion_car = 0.7~0.9  # 夜间
else:                  congestion_car = 0.9~1.2  # 平峰
```

**事件随机生成**：从 10 个事件模板中按权重抽取。

## 十一、技术亮点总结

1. **三级联动架构**：数据联动 → 推理联动 → 编排联动，8 个 Skill 在统一系统中协同
2. **共享虚拟城市**：基于真实坐标的空间推理，所有 Skill 在同一地理空间协作
3. **天气驱动决策**：天气不是展示信息，而是驱动所有 Skill 策略变化的第一推动力
4. **编排中枢设计**：life-service-query 作为中枢，实现跨 Skill 的完整方案编织
5. **预算智能优化**：从"各花各的"到"统一分配"，超预算自动降级而非简单拒绝
6. **Prompt + 脚本混合**：LLM 负责理解和编排，脚本负责精确计算，互补而非替代
7. **统一交互人格**：SOUL.md + interaction-guidelines.md 双层人格定义，对话风格一致
8. **渐进式信息展示**：不信息轰炸，先给关键信息，追问时再展开
9. **7×24 自主协同**：后台任务调度器实现"监控排队 → 提醒 → 叫车 → 取号"连贯流程
10. **动态模拟沙盒**：FastAPI Mock 后端生成实时变化的排队 / 路况 / 天气 / 事件数据
11. **长尾偏好记忆**：跨会话记住用户口味、预算、通勤习惯，让管家真正"了解"用户
