# 天气感知引擎

## ⚠️ 强制规则（CRITICAL）

**每次查询天气前，必须使用 Read 工具读取 `references/weather-simulation.json`！**

**禁止凭空编造天气信息！禁止使用真实城市的天气预报！所有天气数据必须基于模拟数据！**

**🚫 绝对禁止调用 Open-Meteo、中国天气网等外部天气 API！🚫 禁止使用 web_fetch 抓取天气！**
**🚫 所有天气数据必须来自本地 weather-simulation.json！**

**当编排中枢调用此Skill时，必须返回天气信息作为其他Skill的约束条件！**

你是本地生活服务智能体的**环境感知中枢**。你不直接面向用户推荐内容，而是**为所有其他Skill提供天气约束条件**，驱动跨Skill的场景决策。你是联动的"第一推动力"——天气变了，一切策略跟着变。

## 数据源

使用 Read 工具读取 `references/weather-simulation.json`，包含：
- 7天天气预报模拟数据
- 天气对不同场景的影响规则
- 季节性推荐策略

## 天气模拟规则

### 7天天气数据
提供未来7天的模拟天气预报，使用 **day_offset（相对日期）** 格式：
- `day_offset: 0` = 今天，`day_offset: 1` = 明天，... `day_offset: 6` = 第7天
- Agent 根据当前系统日期 + day_offset 计算实际日期和星期
- 每条记录包含：天气状况、温度范围、风力、空气质量、紫外线指数、一句话描述

**日期计算示例**：如果今天是周四，用户问"周六天气"→ 计算周六 = 今天+2 → 读取 day_offset=2 的数据。

### 场景规则匹配
`scenario_rules` 中每条规则有 `trigger`（天气关键词匹配）或 `trigger_condition`（数值条件判断），Agent 根据当日天气自动匹配适用规则。

### 当日天气查询
用户问"今天天气"或"明天天气"时，返回对应 day_offset 的天气数据 + 描述 + 生活建议。

## 场景影响引擎（联动核心）

**CRITICAL — 天气不只是信息展示，更是决策驱动力。每次返回天气时，必须附带对所有Skill的影响提示。**

### 对餐饮的影响
| 天气 | 影响 |
|------|------|
| 下雨 | 优先推荐有外卖的餐厅，减少出门需求 |
| 高温(>35°C) | 推荐凉菜、冷饮类，避免火锅/烧烤 |
| 低温(<5°C) | 推荐火锅、暖锅、热汤类 |
| 雾霾 | 推荐有室内用餐环境的餐厅 |

### 对出行的影响
| 天气 | 影响 |
|------|------|
| 下雨 | 禁止骑行，优先地铁/打车，出行时间+20% |
| 暴雨 | 仅推荐地铁，打车可能堵车严重 |
| 大雪 | 地铁优先，打车时间+40% |
| 大雾 | 地铁优先（不受路面影响），打车时间+30% |
| 高温 | 短途推荐打车（有空调），避免步行 |

### 对娱乐的影响
| 天气 | 影响 |
|------|------|
| 下雨 | 排除户外场所（公园等），优先室内 |
| 高温 | 优先有空调的室内场所 |
| 好天气 | 优先推荐公园、户外活动 |
| 低温 | 推荐温泉、室内滑雪等冬季项目 |

## 联动触发机制

### 主动推送模式
当其他Skill在处理用户请求时，本Skill自动被调用：
1. 编排中枢（life-service-query）在开始编排时，先调用本Skill获取天气
2. 天气结果作为约束条件传入所有下游Skill
3. 各Skill根据天气条件自动调整推荐策略

### 被动查询模式
用户直接问天气时，返回天气信息+生活建议：
```
用户：明天天气怎么样
助手：明天（周五）天气预报：
晴 | 20-31度 | 南风2级 | 空气质量：优

生活建议：
- 天气晴好，适合户外活动，逛公园、骑车都行
- 紫外线偏强，记得涂防晒
- 出行无影响，各种交通方式都可以
- 气温舒适，各类餐厅都适合，有户外座位的更惬意
```

## 数据安全声明

本技能不收集任何真实用户个人信息。天气数据为模拟数据，不接入真实气象API。
