## 一、定时触发器（Cron Jobs）

### 1.1 每日早安播报（08:00）

**触发时间**：每天早上 8:00
**执行流程**：
1. 调用 `weather-awareness` 获取今日天气
2. 读取用户偏好记忆（`~/.openclaw/memory/user-preferences.json`）
3. 检查今日是否有特殊日期（生日/纪念日）
4. 组装早安消息并推送

**早安消息模板**：
```
早！今天{weekday}，{weather}，{temp_low}-{temp_high}度。

{天气相关建议}
{特殊日期提醒（如果有）}
{今日推荐（如果有）}
```

**示例输出**：
```
早！今天周四，多云转晴，18-28度。出门不用带伞，地铁正常就行~

对了，后天是你女朋友生日哦！要不要我帮你提前安排一下？上次你带她去陶艺工坊她挺开心的，今年要不要换个新花样？
```

### 1.2 天气突变预警（每2小时检查）

**触发时间**：每2小时自动检查一次天气变化
**触发条件**：天气状况发生显著变化（晴→雨、温度骤降>5度、空气质量恶化）
**执行流程**：
1. 对比上次天气数据与当前天气数据
2. 如果变化超过阈值，触发预警
3. 调用相关Skill调整已有计划

**预警消息模板**：
```
⚠️ 天气变化提醒：{变化描述}

{影响分析}
{建议调整}
```

### 1.3 周末活动推荐（周五18:00）

**触发时间**：每周五 18:00
**执行流程**：
1. 读取用户娱乐偏好
2. 检查周末天气
3. 推荐1-2个适合的活动

### 1.4 特殊日期提醒（提前3天）

**触发时间**：每天 09:00 检查
**执行流程**：
1. 扫描用户偏好中的 `special_dates`
2. 如果3天内有特殊日期，发送提醒
3. 主动提供安排建议

## 二、事件监控器（Watchers）

**CRITICAL — 这是7×24自主协同的核心能力：持续监控外部事件状态，在条件满足时自动触发行动。**

### 2.1 餐厅排队监控

**场景**：用户想去热门餐厅但需要排队
**监控逻辑**：
1. 用户说"我想去海底捞但怕排队" → 启动排队监控任务
2. 后台每5分钟查询一次模拟沙盒API（`GET /api/queue/{restaurant_id}`）
3. 当排队桌数 ≤ 5桌时，触发提醒
4. 提醒消息中附带"自动叫车"选项

**监控→提醒→执行 连贯流程**：
```
[19:00] 用户：我想去海底捞，但怕排队
[19:01] 小橙：好嘞，我帮你盯着！现在排15桌，等快到了我叫你~

[19:15] (后台监控：排队10桌)
[19:30] (后台监控：排队7桌)
[19:42] (后台监控：排队4桌 ← 触发阈值！)

[19:42] 小橙：海底捞排队还剩4桌了，现在出发刚好！要帮你叫车吗？
         从望京打车过去大概20分钟，¥35左右

[19:43] 用户：叫吧
[19:43] 小橙：好嘞，车已经在路上了，预计8分钟到楼下。
         到了直接去3号桌，我帮你预取号了~
```

### 2.2 优惠到期提醒

**场景**：用户关注的优惠即将过期
**监控逻辑**：
1. 扫描 `deals-data.json` 中有限时条件的优惠
2. 在优惠到期前1天提醒用户
3. 结合用户偏好推荐是否值得使用

### 2.3 出行路况监控

**场景**：用户有固定通勤路线，高峰期路况异常
**监控逻辑**：
1. 工作日早高峰（7:00-9:00）和晚高峰（17:00-19:00）检查路况
2. 如果检测到异常拥堵（模拟），主动提醒提前出门或改路线

### 2.4 预算花销追踪

**场景**：用户设定了月度预算
**监控逻辑**：
1. 追踪本月已产生的推荐消费
2. 当消费接近预算80%时提醒
3. 自动切换到省钱模式推荐

## 三、任务编排器（Orchestrator）

### 3.1 后台任务生命周期

```
用户请求 → 创建后台任务 → 注册监控器 → 条件满足 → 执行动作 → 推送结果 → 任务完成/继续监控
```

### 3.2 任务状态机

| 状态 | 说明 | 下一步 |
|------|------|--------|
| `PENDING` | 任务已创建，等待启动 | → `WATCHING` |
| `WATCHING` | 监控中，持续检查条件 | → `TRIGGERED` 或 `EXPIRED` |
| `TRIGGERED` | 条件满足，准备执行 | → `EXECUTING` |
| `EXECUTING` | 正在执行动作（叫车/预约等） | → `NOTIFIED` |
| `NOTIFIED` | 已通知用户，等待确认 | → `COMPLETED` 或 `CANCELLED` |
| `COMPLETED` | 任务完成 | — |
| `EXPIRED` | 超时未触发，自动过期 | — |
| `CANCELLED` | 用户取消 | — |

### 3.3 任务配置格式

后台任务存储在 `references/scheduled-tasks.json`：

```json
{
  "task_id": "queue_watch_001",
  "type": "queue_monitor",
  "status": "WATCHING",
  "created_at": "2025-06-06T19:01:00Z",
  "expires_at": "2025-06-06T22:00:00Z",
  "config": {
    "restaurant_id": "R13",
    "restaurant_name": "海底捞",
    "threshold_tables": 5,
    "check_interval_min": 5,
    "auto_call_car": true,
    "user_location": "user_home"
  },
  "history": [
    {"time": "19:05", "queue_count": 15, "action": "continue_watching"},
    {"time": "19:15", "queue_count": 10, "action": "continue_watching"},
    {"time": "19:30", "queue_count": 7, "action": "continue_watching"},
    {"time": "19:42", "queue_count": 4, "action": "TRIGGERED"}
  ]
}
```

## 四、Cross-Skill 联动规则

### 1. ← 天气联动
- 天气突变时，自动触发预警推送
- 如果用户已有今日计划，自动调用编排中枢调整方案

### 2. → 餐饮联动
- 排队监控触发后，通知用户并推荐出发时间
- 优惠到期前，推荐用户去使用优惠

### 3. → 出行联动
- 排队触发后，自动计算出发路线和预估到达时间
- 路况异常时，主动推荐替代路线

### 4. → 优惠联动
- 发现新的限时优惠时，主动推送给用户
- 预算接近上限时，自动切换到优惠优先模式

## 六、与模拟沙盒的交互

**CRITICAL — 后台监控器通过 HTTP 请求与动态模拟沙盒（FastAPI Mock Backend）交互，获取实时动态数据。**

沙盒API地址：`http://localhost:8900`

| API 端点 | 用途 | 调用频率 |
|---------|------|---------|
| `GET /api/queue/{restaurant_id}` | 查询餐厅排队情况 | 每5分钟 |
| `GET /api/traffic` | 查询路况信息 | 每30分钟 |
| `GET /api/weather/realtime` | 查询实时天气变化 | 每2小时 |
| `POST /api/car/call` | 模拟叫车 | 用户确认后 |
| `POST /api/reservation` | 模拟预约/取号 | 用户确认后 |
| `GET /api/events` | 查询动态事件流 | 按需 |

## 七、兜底策略

| 情况 | 处理方式 |
|------|---------|
| 沙盒API不可用 | 退化为静态数据模式，提示用户"实时监控暂时不可用" |
| 监控超时（3小时无变化） | 自动过期，通知用户"今天人太多了，要不改天？" |
| 用户不回复推送 | 5分钟后再提醒一次，之后不再打扰 |
| 多个任务同时触发 | 按优先级排序：排队监控 > 天气预警 > 优惠提醒 |

## 数据安全声明

本技能不收集任何真实用户个人信息。排队数据、路况数据均为模拟沙盒生成的动态数据，不接入任何真实平台API。
